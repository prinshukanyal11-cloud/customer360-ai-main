Phase 12: testing, security review, performance, CI/CD, deployment. — backend (the review began by comparing every control claimed in docs/security.md against the code, and three were documented but absent: rate limiting existed only as unread config keys (rate_limit_enabled/rate_limit_per_minute in config.py and .env.example, no limiter anywhere), no security-header middleware set a single header, and jwt_secret/secret_key defaulted to the literal "change-me" - so a deployment that forgot to set them signed tokens with a key published in this repository, a complete authentication bypass that started without complaint. All three now exist: app/middleware/rate_limit.py (fixed window per client, /auth/* on a tighter auth_rate_limit_per_minute because login is the only endpoint where a credential can be guessed, 429 with Retry-After and the standard error envelope, health/ready exempt so an orchestrator probe cannot be throttled, X-Forwarded-For ignored unless rate_limit_trust_proxy is set because trusting it unconditionally would let any caller forge the key and escape the limit); app/middleware/security_headers.py (nosniff, DENY, no-referrer, Permissions-Policy, COOP/CORP, HSTS in production only, CSP on the docs routes only because Swagger loads from a CDN); and Settings._reject_insecure_production_config, which refuses to boot a production deployment with a placeholder or <32-char secret, DEBUG=true, a wildcard CORS origin, or an empty DATABASE_URL_RO that would hand NL-to-SQL a read-write connection - development still runs on the shipped defaults so a fresh clone needs no ceremony. Two defects fixed alongside: decode_token now validates that sub is a positive integer, because get_current_user and /auth/refresh did int(payload["sub"]) on unvalidated claims and turned a malformed token into a 500 with a stack trace instead of a 401; and train_churn_model, a Celery stub that returned {"status": "COMPLETED"} without training anything, now raises NotImplementedError - it was the one place the codebase reported a comfortable lie rather than admitting a gap. Testing: app/tasks/tasks.py had 0% coverage, leaving the two paths that actually run in production (the dataset worker and the scheduled drift sweep) unverified - tests/test_tasks.py covers tenant rejection, the FAILED status the worker writes when the pipeline raises, session release on failure, and the sweep's refusal to abort on one bad model version; the refresh/logout/deactivated-user auth paths also had zero coverage and are now tested; tests/test_migrations.py asserts migration/metadata index agreement as a local proxy for the alembic check CI runs against real PostgreSQL (it catches exactly the drift Phase 11 shipped, where migration 0002 created ix_monitoring_runs_org_version_created but the model never declared it). Coverage rose to 92% overall with a 90% CI floor. Performance: migration 0003 adds the three composite indexes the service layer's predicates actually justify - predictions (organization_id, model_version_id, customer_id), which every dashboard risk count, drift histogram, and predictions export is scoped by and whose sort the export can take from the index; model_versions (organization_id, active), the gateway to scoring, drift, and campaign audience resolution; and customer_features (organization_id, dataset_version_id), without which the drift comparison against one training dataset version reads every feature row the tenant owns, since the existing uniqueness constraint leads with customer_id - deliberately limited to measured hot paths, because score_customers deletes and reinserts all prediction rows per version and every extra index is paid for on that write. reportlab was dropped from requirements.txt: PDF export is deferred and the catalogue reports pdf_status not_available, so the renderer was ~50MB of unused dependency and supply-chain surface. CI/CD: ci.yml rewritten with ruff over app+tests+scripts+migrations (it previously linted only backend/app), a coverage floor, an alembic check plus downgrade/upgrade cycle against a real PostgreSQL service, the E2E smoke test as its own job, and pip-audit/npm audit/gitleaks; deploy.yml's "deployment artifact" was a tarball of /dev/null and now builds and pushes both images to GHCR with commit-SHA tags, GHA caching, and packages:write as its only elevated permission. Frontend: npm run lint had referenced eslint since the scaffold but shipped no config, so it had never run; frontend/.eslintrc.cjs makes it pass with zero errors and CI now enforces it) and docs (security.md documents the findings, the per-process limiter scope, the proxy-header trade-off, and three items left open - refresh tokens are not revocable, there is no account lockout, and prompt injection is mitigated by construction but not fuzzed; deployment.md documents the fail-closed production config, the TLS/proxy settings, and what each CI job protects)
Phase 13: close-out of the three items Phase 12 left open, plus browser E2E. — backend (refresh tokens were un-revocable, so /auth/logout returned 204 while the token stayed valid for its remaining 7 days; they are now stored hashed - SHA-256 of the token alongside jti, user_id, org_id, family_id, expires_at, revoked_at, revoked_reason - in refresh_tokens, migration 0004, so a database dump no longer yields usable credentials. POST /auth/refresh rotates: it returns a new pair and revokes the presented token, and because a client bug and a stolen token look identical from the server's side, presenting an already-revoked token revokes the entire family and forces a fresh sign-in rather than letting a compromise continue. POST /auth/logout revokes every live refresh token for the user. The deliberate limitation is stated in security.md rather than hidden: access tokens stay stateless and valid until access_token_expire_minutes, so logout ends the session, not an in-flight bearer token. account lockout (LoginFailure rows, migration 0004) keyed on the normalised submitted address rather than on account existence, with identical wording for unknown, wrong-password, and locked cases so the response cannot be used to enumerate users; the threshold (default 5) is set where it stops guessing rather than where it lets anyone who can reach a login form lock a colleague out. Rate limiting grew a pluggable counter store - memory, or Redis for a deployment-level budget across replicas, selected by RATE_LIMIT_BACKEND with auto preferring Redis and degrading to memory rather than taking the API down with it - so the per-replica multiplication that Phase 12 could only document is now fixable by configuration. Prompt injection, previously mitigated by construction but unfuzzed, is now tested: ai_analyst wraps retrieved text in CONTEXT/HISTORY/QUESTION fence markers and neutralise_untrusted strips newlines and forged fence markers before the payload reaches the prompt, so a retrieved record cannot close the block it was quoted in; the SELECT-only guards stay the real containment boundary. Frontend: the gaps that made the backend work unreachable from the browser were the actual story here - there was no refresh interceptor at all, so a 30-minute access token expiry silently ended the session and the stored refresh token was dead weight; there is now a single-flight interceptor that shares one in-flight refresh across all requests (without it, five panels loading at once would each spend the stored token and the family-revocation rule would log the user out), retries the original request, and clears storage when the refresh itself fails rather than retrying a dead token in a loop. Sign out called clearTokens() only, so it hid the sign-in form while the token remained valid - it now calls /auth/logout first. API_BASE was hardcoded, making VITE_API_URL (documented in .env.example) dead configuration; it is read from the environment now, and vite's unused /api proxy to port 8000 was removed, since it only ever made a misconfigured base URL fail confusingly. Playwright browser E2E (frontend/e2e/auth.spec.ts, npm run test:e2e) covers what the API-level smoke test structurally cannot: that the client stores the rotated token rather than the one it just spent, that a transparent re-auth works, and that logout revokes server-side. It builds the real bundle and serves it with vite preview, and boots the API against a throwaway SQLite file built from the models, so it needs no PostgreSQL in CI. Wiring it up found the last two findings of the project: vitest was collecting the Playwright specs and failing, and tsconfig included only src,  The last defect was found by using the product: Data Upload reported failure while the endpoint answered 422 Field required, because the axios instance declared a default Content-Type: application/json, and that default makes transformRequest serialise FormData into a JSON object instead of leaving it for the browser to encode as multipart - a File has no enumerable properties, so neither filename, boundary, nor a single byte of the file crossed the wire. The header is now deliberately absent from the instance, guarded by frontend/src/__tests__/api-client.test.ts, which asserts FormData survives transformRequest and fails if the default returns, and frontend/e2e/dataset-upload.spec.ts, which drives a real file input and requires a 201 with the parsed row count and which reproduces the original 422 when the header is put back. CI/CD: new e2e job installing the pinned Chromium via --with-deps and uploading traces and screenshots. Docs: security.md no longer lists the three items as open and documents the rotation/lockout semantics and their limits; api.md documents single-use refresh tokens and the non-enumerating lockout response; deployment.md documents RATE_LIMIT_BACKEND, the login-lockout settings, and the four testing tiers.


## 11. Technology Justification (summary)
- React+TS+Vite+Tailwind+shadcn: modern, typed, fast DX, shadcn components for SaaS look. Recharts/Plotly for interactive analytics.
- FastAPI+Pydantic: async, typed, OpenAPI auto, validation-first.
- PostgreSQL+SQLAlchemy+Alembic: relational integrity, multi-tenant friendly, migrations.
- Pandas/Polars+sklearn+XGBoost+LightGBM: mature, interpretable, model registry/caching, robust.
- SHAP: industry-standard local/global explainability.
- Celery+Redis: reproducibility, async training, drift jobs.
- Provider abstraction for LLM (OpenAI/Gemini-swappable).
- Docker+Compose+GH Actions: QA-reproducible, deployable.

## 12. MVP vs Advanced
MVP (project must-haves): auth, upload+mapping+validation ?, ingesting clean data ?, customer 360 basics, RFM, K-Means segmentation, churn pipeline+metrics, churn risk categorization, SHAP, CLV, at-risk dashboard, retention recommendations, cohort analysis, campaign builder+simulator, AI Analyst with retrieved-data-only answers, NL-to-SQL with safety, dashboard KPIs, exports (CSV/Excel), health endpoints ?, tests for core ML/API ?, Docker, docs, CI.

Advanced (nice-to-have/robustness): A/B testing with statistical rigor, product recommendations, next-purchase prediction, customer journey depth, PDF reports, model drift monitoring UI, LLM multi-turn session memory, user management RBAC UI, audit log viewer, multi-tenant org admin, rate limiting UI configuration, PDF report branding, advanced caching.
